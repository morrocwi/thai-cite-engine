# Known issues — v1 build (updated 2026-09-20 after the adapter/router/Citation-Use expansion)

## Confirmed critical defect (as of the first validation run, 2026-09-20): G6 relevance gate

The first 100-scenario adversarial concept-validation run found a **systemic, architectural
defect** in what was then the sole relevance gate, in `src/thaicite/evidence/verifier.py`.
That gate checked keyword overlap between the free-text `context` field (or the harness's
own scenario-metadata prose) and a candidate's title/abstract — it never compared a
returned candidate's title/author/year against the actual citation string being verified.
Combined with a stopword list missing common words, any OpenAlex hit sharing even one
generic word with the free-text context cleared relevance and was stamped `VERIFIED`,
whether or not it was the work actually being cited.

The clearest evidence was the **POSITIVE_CONTROL category: 15/15 FAIL** — every well-known,
real, unambiguously-indexed paper tested (Watson & Crick 1953, Kahneman & Tversky 1979,
Vaswani et al. 2017, and others) either vanished from the output while unrelated real
papers were confidently marked `VERIFIED` in its place, or sat alongside several unrelated
false-positive `VERIFIED` entries. Every false-positive `VERIFIED` record carried a real,
traceable DOI, so a downstream user had no signal that the "verified" citation did not
correspond to what was cited. Full findings, all 23 critical cases, and the per-category
breakdown: `tests/golden/CONCEPT_VALIDATION_REPORT.md`.

## What changed after the finding

`src/thaicite/evidence/verifier.py` was redesigned so gate G6 checks the returned
candidate's own title/authors against the **query citation string itself** (never against
free-text `context`), via a token-set/edit-distance similarity measure plus author-surname
overlap — a single shared generic word is no longer sufficient, and this identity check is
now REQUIRED: a candidate that fails it cannot reach `VERIFIED` even if every other gate
passes. The old context-relevance signal survives only as a non-gating informational field
(`G6b_context_relevance_signal_nongating` / `context_matched_keywords`), never as a
substitute for the identity check. See the module docstring and the "Historical note" in
`src/thaicite/evidence/verifier.py` for the exact before/after.

## Current status — honestly stated

A full live revalidation re-run against the same 100 adversarial scenarios has **not** yet
completed cleanly: a meaningful fraction of the run window fell inside an OpenAlex
shared-IP free-tier daily rate limit (HTTP 429), which produces `INCONCLUSIVE` verdicts for
any scenario that could not reach a candidate-fetch or merge/verify code path. The best
reproduction available right now is `tests/golden/RUNNER_OUTPUT_LATEST.md`
(30 PASS / 0 FAIL / 70 INCONCLUSIVE — the 0 FAIL is real, but most of the suite is
INCONCLUSIVE due to rate-limiting, not confirmed PASS), generated by
`tests/run_adversarial_suite.py`.

**This fix is not proven by a clean live 100/100 re-run.** What is verified: (1) the
G6 identity-vs-query logic exists and is unit-testable independent of live network access,
and (2) no scenario in the latest run produced a live `FAIL`. What is *not* yet verified:
a live re-run of all 15 POSITIVE_CONTROL scenarios reaching a definitive (non-INCONCLUSIVE)
`VERIFIED`-on-the-correct-work outcome, because OpenAlex rate-limiting prevented most of
them from completing. Do not treat this prototype as cleared until a rate-limit-free
re-run (or a mocked-transport re-run of the same scenarios) reproduces the fix against the
same adversarial set with a definitive verdict.

## Since this file was first written: full v1 build (same session, 2026-09-20)

The G6 fix above was followed by a substantial expansion, unit-tested (79/79 passing) but
**not yet covered by its own adversarial live run** — the founder's explicit instruction was
to build the full system first and defer the next live 100-scenario test until after. Newly
implemented and individually tested, but not yet stress-tested together at the same scale as
the original 100-scenario run:

- **Crossref and PubMed adapters** — live-verified against their real APIs this session.
- **ThaiJO adapter** — implemented against the documented OAI-PMH protocol shape, but its
  base endpoint URL is an **unverified assumption**: the classic
  `https://www.tci-thaijo.org/index.php/index/oai` path returned HTTP 404 when checked live
  (ThaiJO's public site appears to have moved off that path). The adapter correctly reports
  this as `PARSER_ERROR`, not `NOT_FOUND` (the "real failure ≠ no results" invariant holds
  even against a broken assumed endpoint) — but **no live ThaiJO result should be trusted
  until the correct endpoint is confirmed and this note is updated.**
- **Thai-first Source Router** — ThaiJO ordered first for THAI/THAI_HEALTH/GENERAL domains,
  unit-tested for ordering and for graceful continuation when a simulated adapter fails, but
  not yet exercised against a large live adversarial set.
- **Citation-Use model + 3-way ADMIT/REJECT/HOLD gate** — unit-tested with hand-picked
  cases (including a same-work/different-claim divergence test proving `SUPPORTS`→`ADMIT`
  vs. `CHALLENGES`→`REJECT` for the identical evidence text under different claimed intents),
  not yet stress-tested adversarially at scale.
- **New, predictable risk not yet covered by any test:** a Thai-language citation whose
  indexed record carries an English-translated title would likely show near-zero G6
  title-token overlap even for the correct work, since the current identity check is
  token-based with no translation/transliteration awareness. This should be added as its own
  adversarial test category (e.g. `THAI_TITLE_TRANSLATION_MISMATCH`) in the next 100-scenario
  run, rather than discovered the same way the original G6 defect was.
